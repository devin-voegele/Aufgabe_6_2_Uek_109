OpenShift – Connectors

UeK 109 · html-openshift-app + PostgreSQL · Stand 2026-06-04

Jeder rote Punkt im Diagramm ist eine Referenz zwischen zwei Ressourcen: eine Ressource nennt den Namen oder die Labels einer anderen. Die gelb markierten Werte müssen auf beiden Seiten exakt übereinstimmen – sonst findet OpenShift das Ziel nicht.
Internet→ HTTPS →Route (R)
Die Route veröffentlicht den Service nach außen und terminiert TLS (edge), http wird auf https umgeleitet.
040-route.yaml
kind: Route
spec:
  tls:
    termination: edge
    insecureEdgeTerminationPolicy: Redirect
Route (R)→Service (S)
Route zeigt per spec.to.name auf den Service-Namen, und port.targetPort auf den benannten Service-Port.
040-route.yaml
kind: Route
spec:
  to:
    kind: Service
    name: html-openshift-app
  port:
    targetPort: http
030-service.yaml
kind: Service
metadata:
  name: html-openshift-app
spec:
  ports:
    - name: http
      port: 8080
      targetPort: 8080
Service (S)→Pod (P)
Der Service findet seine Pods über spec.selector, der mit den Pod-Labels (aus dem Deployment-Template) übereinstimmen muss.
030-service.yaml
kind: Service
spec:
  selector:
    app: html-openshift-app
020-deployment.yaml (Pod-Template)
kind: Deployment
spec:
  template:
    metadata:
      labels:
        app: html-openshift-app
HPA→Deployment (D)
Die HPA skaliert das Deployment, das sie per scaleTargetRef.name referenziert.
050-hpa.yaml
kind: HorizontalPodAutoscaler
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: html-openshift-app
  minReplicas: 1
  maxReplicas: 3
020-deployment.yaml
kind: Deployment
metadata:
  name: html-openshift-app
Deployment (D)→Pod (P)
Das Deployment verwaltet seine Pods über selector.matchLabels, das mit den Template-Labels übereinstimmen muss.
020-deployment.yaml
kind: Deployment
spec:
  selector:
    matchLabels:
      app: html-openshift-app
  template:
    metadata:
      labels:
        app: html-openshift-app
Secret (S.E)→Deployment (D)
Der Container holt env-Vars aus dem Secret: secretKeyRef.name = Secret-Name, key = ein Key unter data:.
020-deployment.yaml (DB-Container)
env:
- name: POSTGRESQL_USER
  valueFrom:
    secretKeyRef:
      name: html-openshift-app-database
      key: database-user
100-postgres-secret.yaml
kind: Secret
metadata:
  name: html-openshift-app-database
data:
  database-user: dXNlcg==
  database-password: cGFzc3dvcmQ=
  database-name: ZGF0YWJhc2U=
Pod (P)→PVC
Das Volume des Pods bindet das PVC per persistentVolumeClaim.claimName = PVC-Name. Der volumeMounts.name verknüpft Volume und mountPath im Container.
020-deployment.yaml (Pod)
volumeMounts:
- name: auftrag-6-2-vol
  mountPath: /tmp
volumes:
- name: auftrag-6-2-vol
  persistentVolumeClaim:
    claimName: auftrag-6-2
010-pvc.yaml
kind: PersistentVolumeClaim
metadata:
  name: auftrag-6-2
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 1Gi
